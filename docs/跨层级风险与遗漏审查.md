# 跨层级风险与遗漏审查

优先级按“能否使路线失效”划分，不用伪造概率打分。P0 为必须在定线前关闭的问题；P1 为分日和出发前验证；P2 为体验与优化。当前 P0 均未关闭，所以不能发布最终可执行路线。

| 层级/问题 | 联动失效链 | 优先级 | 验证与应对 |
|---|---|---|---|
| 起终点不明确 | 错校区/错终点→漏算出城/过江→时间与路线错误 | P0 | 明确校门和汉阳目的地，设精确控制点 |
| 骑行合法性/路线连续性 | 汽车路/新隧道→禁行→绕行爬升/住宿全部变化 | P0 | 每条关键边查标志/官方信息，绕行必须独立连通 |
| 公路车适配 | 路面缺标签→碎石/坑洼→爆胎/速度骤降→夜骑 | P0 | 路面未知段清单、近期路况、胎宽负重匹配；不默认为铺装 |
| 灾害和天气 | 暴雨→滑坡/断路→谷地无撤离→补给电量耗尽 | P0 | 天气+道路+上游雨情联合判断，预先留退出节点 |
| 桥隧和城市交通 | 夜间到达→禁行桥/高架→无合法末段 | P0 | 汉阳进城单独验证，时间留余量 |
| 体能随训练变化 | 未来能力过度乐观→连续疲劳→高温决策失误 | P1 | 用阶段实测更新能力区间，连续多日恢复比单次纪录更重要 |
| 距离与日照 | 250 km + 爬升 + 午休→超出安全时段 | P1 | 先时间和住宿节点后里程，提前缩短日程 |
| 补水/补能 | 高温需水增加→负重增加→爬坡慢→水耗尽 | P1 | 按实测需求和可确认供水间隔配置容量及备用，未验证山泉不可依赖 |
| 住宿 | 城镇有酒店但满房/晚到/不收车→继续夜骑 | P1 | 当日电话确认入住、车存放、取消政策；前后节点备选 |
| 车辆与故障 | 刹车/轮胎故障+长下降+无维修店 | P1 | 出发前保养和负重测试；适配备胎/补胎工具/链条件，学会基础维修 |
| 电子设备与导航 | 雨热/电池耗尽→断网迷路→偏离安全路线 | P1 | 两种离线备份、纸面关键节点、电量预算和防水充电方案 |
| 数据误差 | GCJ-02/WGS84 混用→吸附错路→误入高架 | P0 | 坐标来源可追溯，控制点对照，转换后审查 |
| 高程误差 | DEM 隧道地表峰→虚假爬升→日程误分 | P1 | 桥隧标记与海拔来源分离，平滑敏感性及气压轨迹比对 |
| 应急/通信 | 无信号+单人+不知道位置→救援延迟 | P1 | 按节点报平安、离线定位、同伴/紧急联系人、110/120/122 与本地救援渠道核实 |
| 时间/预算/运输 | 天气延误→被返程期限逼迫赶路 | P1 | 预留机动日和资金，验证客运/铁路携车或托运规则及车站可达性 |
| 数据许可/隐私 | 导出再分发限制/家庭住址暴露→成果不可分享 | P1 | 保存许可与授权范围，公开版本模糊个人端点，不提交密钥 |
| 体验偏好 | 偏好景点绕行→新增山路→时间不足 | P2 | 仅在所有硬风险满足后加入可删除支线 |

## 检查门与证据要求
G0 技术门：合法可访问的数据源，至少一条短段真实骑行响应及另一独立依据；当前未通过联网路线部分。
G1 路网门：起终点确认，关键桥隧/旧线与所有分段连通，无未处理禁行；当前未通过。
G2 适配门：路面、坡长、车辆、连续骑行能力、补给/住宿/撤离相匹配；当前未通过。
G3 行前门：日期、预报、官方路况、酒店、装备和 GPX 设备测试通过；2027 出发前执行。
G4 途中门：每日滚动复核天气和下个安全节点，异常触发缩短/等待/撤离；禁止按预设里程覆盖现场信息。

每次换线必须重查：是否引入禁行、增加坡长、延长无补给区、取消住宿、改变过江、进入新的天气区、超过电量/日照。两个备选若依赖同一座桥或同一条山谷，不算独立备份。

## 决策日志字段
日期、问题 ID、位置/道路方向、证据 URL 与时间、事实/推测级别、影响范围、决策、替代方案、复查期限、关闭依据。官方临时封控优先于旧轨迹；现场标志优先于算法。近期实骑也只能证明当时某种车辆通过，不能替代最新管制。
