## 实测 Python 工具与能力边界
安装版本锁定于 `requirements.lock`。gpxpy 解析轨迹；pyproj 计算椭球距离与投影；Shapely 检查几何；rasterio 读取/采样栅格；NetworkX 对有向图过滤禁行边并计算路径。测试使用内存合成数据，绝不是西安—武汉道路验证。OSMnx 仅读取官方说明，未安装或运行；GeoPandas 未安装，当前最小流程无需它。

`analyze_gpx.py` 只计算每个 track segment 内点间测地线距离，保留段间断裂，不连接断段。报告高程缺失率、原始升降总和和超过 1 km 的稀疏边；1 km 只是复核提示，不是道路安全阈值。原始累计爬升容易被噪声放大，当前工具没有平滑、道路吸附或可信坡度功能。无高程时返回 null，不把缺失当零。未检测所有 GPX 扩展、异常时间和跨日重叠，正式导入仍须人工检查。

## 坐标、高程和轨迹处理
D（工程常识，产品具体约定须复核）：GNSS/GPX 和 OSM 通常使用 WGS84；高德中国大陆坐标使用 GCJ-02。GCJ-02 不是把 EPSG 代码换成 4326 就能转换的投影。pyproj 的 UTM 往返测试不证明支持 GCJ-02。不同来源不得直接叠加测距；记录原始坐标、转换来源/版本和误差。在合法支持的转换路径确定前，高德结果保持原始 JSON，不生成“WGS84 GPX”。严禁凭目测平移冒充转换。

DEM 的水平 CRS、垂直基准、分辨率、采集日期、NoData、空洞填补均需记录；DSM 可能含林冠/建筑。桥梁和隧道处地表高程不等于路面高程。30/90 m 等分辨率示例不代表已获得对应产品，短陡坡可能被平均掉。坡度计算需在投影或测地距离上做纵向采样；用 50/100/200 m 等多个窗口进行敏感性比较并注明选择，不以相邻噪声点的最大坡度定难度。

GPX 可以承载轨迹点，但不保证保留转向导航、道路禁行、路面属性、航点和 App 扩展。下一阶段往返测试需比较点数、分段、距离、坐标、海拔、航点和离线导航。设备自动重算可能改走高速/坏路，测试固定轨迹跟随与偏航恢复。

## 许可和交叉验证
D：OSMnx README 明示自身 MIT，OSM 数据有署名要求；具体 ODbL 分发义务应在公开派生数据库前阅读版权页。高德/行者的轨迹缓存、批量访问和再分发条款未核实，不默认允许。官方 README 快照保留来源与哈希，公开传播前审查对应软件/文档许可证；本仓库未擅自给所有第三方内容统一授权。

验证顺序：同一组校门/路口控制点 → 高德合法骑行输出 → OSM 引擎路径 → 逐段检查差异 → 当地交警/道路管理通告和近期路况 → 出发前复核。两图一致只是候选增强，不是通行证明；两个 OSM 产品共享缺失风险。轨迹贴合道路只能证明几何合理，不能证明路面、照明、货车流量和施工情况。

## 可重复操作
从仓库根目录执行：
```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m unittest discover -s tests -v
python3 scripts/probe_sources.py
.venv/bin/python scripts/analyze_gpx.py /path/to/authorized-wgs84-track.gpx
```
联网脚本会刷新同名证据文件；需要历史比较时先复制整个 evidence 目录并保留时间。HTTP 200 仍需检查页面/JSON，不能仅凭状态码认定功能成功。`scripts/amap_probe.py --help` 给出接口实验参数；仅在当前文档确认接口、配置 Key 和域名后使用，参数必须是服务要求坐标。脚本不打印 Key、不记录请求 URL、不覆盖已有输出，并检查业务错误/paths；本轮未成功调用带 Key 请求。
