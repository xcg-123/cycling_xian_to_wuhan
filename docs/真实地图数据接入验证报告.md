原始安全摘录：`CONNECT tunnel failed, response 403`；响应头含 `HTTP/1.1 403 Forbidden`、`server: envoy`。证据为 `data/evidence/phase2/connectivity.json`。没有打开 curl verbose，也未记录请求凭据、Cookie 或私有代理日志。

`environment_status.json` 保存当时 `observations_current=true`、`network_policy.state=enforced` 和有效域名列表。`historical_diagnosis.json` 将原 20 项失败逐条与当前策略对照：20/20 不在允许列表。当前策略观察不单独证明所有历史时刻状态，但与第一阶段相同 CONNECT 403 记录及当前代表复测一致。

### 故障分层结论
- **已验证**：代理可被访问；对未放行目标的隧道建立被拒；允许域名的 HTTPS 请求能完成。因此不是“整个环境无法联网”。
- **强证据归因**：域名未放行是当前阻断；没有额外代理拒绝原因码，不能进一步断言底层策略引擎的全部内部原因。
- **未发生/无法检查**：目标站点 TLS 握手、证书链和目标 HTTP 返回；curl 的默认 `ssl_verify_result=0` 在 CONNECT 被拒时不代表已验证目标证书。
- **没有证据支持**：把失败归因于源站封 IP、DNS 故障、TLS 证书错误、API Key 失效或坐标参数错误。域名解析由代理处理，额外本地 DNS 测试不能证明代理到源站的解析结果。
- **独立缺口**：`AMAP_API_KEY` 与 `AMAP_KEY` 未设置，环境无已声明凭据。Key 缺失没有导致这次 CONNECT 403，因为请求尚未到鉴权层。

## 3. 高德 v5 接入流程及边界
客户端已从第一阶段 v4 更新为用户指定的官方目标：
`https://restapi.amap.com/v5/direction/bicycling`。

匿名测试和带 Key 测试是两个命令。带 Key 客户端只从 `AMAP_API_KEY` 环境变量读取，固定 HTTPS 主机，拒绝重定向，最多读取 5 MB，隐藏异常中的 URL，递归脱敏响应内可能回显的 Key。不接受命令行 Key，不自动复制凭据到文件，不覆盖既有输出。凭据代理占位变量仅代表绑定，之后仍应以 API 业务响应验证可用性。

预备解析器检查 v5 `status=1`、`infocode=10000`、`route.paths[].steps[].polyline`，请求包含 `show_fields=polyline`，读取 distance 和道路分段。**当前官方文档被拦截、无真实成功响应，所以这些字段适配目前仅由合成样本测试，仍须以官方文档和首个实际响应校准。** 不宣称已验证 v5 配额、收费、限制或桥隧字段。

几何审查：坐标范围/有限数值、每段至少两点、重复点、段内超长边、段间断口、轨迹与返回距离相对差异。默认 1 km 边长、5 m 接口断口、10% 距离差是复核阈值，不是服务精度承诺或安全标准；适合短段初筛，稀疏轨迹需要调整并解释。不会连接断段填造道路，不能以几何连续认定沿道路合法。

桥隧：道路名称含“桥/隧道”只记录候选线索；无该名称不代表没有桥隧。保留返回字段名及原始响应供后续检查；当前不能输出完整桥隧清单，也不能依名称判禁行。

坐标：高德结果按 GCJ-02 管理，不能仅改名为 WGS84。解析器中的 GCJ 数值距离只作诊断，不作为严格 WGS84 测距。**未实现或验证 GCJ-02→WGS84 转换，GPX 导出会明确拒绝 GCJ-02。** WGS84 输出仅接受来源可证明的输入；不得通过修改 `source_crs` 绕过检查。高德坐标转换服务是否提供所需逆向转换必须查当前官方文档，不能预设。

## 5. 重试与本地备用方案
在仓库根目录、Python 3.12 环境运行；最少客户端依赖可安装 `gpxpy==1.6.2 pyproj==3.8.0`，完整复现用 `requirements.lock`。下面 `/tmp` 示例适用于 Linux/macOS；Windows 可使用 WSL 或改为当地临时目录。真实起终点先从官方地图选取并记录来源；短测不依赖最终校区。

```bash
python3 scripts/diagnose_network.py --output /tmp/connectivity-new.json
# 只有网络放行且安全凭据已配置后执行。
# 以下坐标是西安附近的技术测试请求点，不是已核实校门或道路入口。
.venv/bin/python scripts/amap_probe.py \
  --origin '108.980000,34.250000' --destination '108.990000,34.250000' \
  --input-crs GCJ-02 --output /tmp/amap-v5-response.json
.venv/bin/python scripts/route_pipeline.py /tmp/amap-v5-response.json \
  --format amap-v5 --output /tmp/amap-v5-audit.json
```

预期顺序是 CONNECT 放行 → 取得服务 HTTP/业务响应 → 用真实 Key 验证鉴权 → 获得 paths/steps/polyline → 比对真实道路位置 → 必要时处理坐标。即便无 Key 返回明确鉴权错误，也只能说明到达了服务处理层，不能算成功路线。失败时区分业务错误码、配额、参数和无路，不以 HTTP 200 代替成功标准。

**备用优先顺序**：
1. 其他合法数据源：OSM API/Overpass 可供路网；BRouter 可沿 OSM 算路，但读到原始路网不等于取得骑行路线。当前对应域名也受云策略限制，换服务不能自动解决同类阻断。开放一个 OSM 入口后先做小片区检查，再决定是否需要引擎；暂不搭建复杂服务器。
2. 若云配置短期无法修复，优先在用户自己的本地 Codex/电脑，按上面的相同命令调用官方 API，使用本机安全凭据。先匿名连通性，再鉴权，最后把脱敏响应、请求点的坐标来源、时间和服务模式交回云端。**本机的网络与权限本轮无法代为验证**；该方案是独立环境的正常授权访问，不是给云环境搭建转发代理。
3. 若已有行者官方账号，可在官方 App/网页创建非敏感的 2—5 km 短骑行路线，确认沿路规划、官方导出权限和 GPX 坐标约定后导出。不要抓私有接口。若官方不支持当前账号导出，转用明确支持合法 GPX 导出的工具或真实 GNSS 记录，不手绘直线补齐。行者版本、会员要求和坐标系目前仍 U。

收到有依据的 WGS84 GPX 后直接运行 `analyze_gpx.py`；它不需要网络。若收到已确认 WGS84 的分段坐标，可按下列规范 JSON 导出：`source` 写清提供者/时间/坐标依据，`source_crs` 为 WGS84，`segments` 为真实的 `[lon,lat]` 二维数组，`reported_distance_m` 可选，`test_only=true`。不把任何示例坐标充当真实输入。

```bash
.venv/bin/python scripts/analyze_gpx.py /path/to/authorized-wgs84.gpx
.venv/bin/python scripts/route_pipeline.py /path/to/verified-wgs84.json \
  --format normalized --output /tmp/route-audit.json --gpx /tmp/TEST_ONLY-route.gpx
```

GPX 输出明确标记 TEST_ONLY，保留分段，不填零海拔，不加入未证实桥隧或转向导航。即使结构正确，也需地图叠加和实体设备离线检查。
